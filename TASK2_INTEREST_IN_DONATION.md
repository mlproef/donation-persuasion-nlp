# Задача 2: Определение заинтересованности в донате

## Цель задачи

Определить, насколько человек заинтересован в донате:
- **0** = отказ (refusal)
- **1** = нейтрально (neutral)
- **2** = заинтересован (interested)

Началось с простой MNLI проверки, развилось до fine-tuning модели и кластеризации для поиска дополнительных данных.

### Этап 1: Начало - MNLI проверка одной гипотезы 

#### Скрипт: `bsp2.py` (строки 36-62)

**Что делали:**
- Использовали **MNLI модель** (`roberta-large-mnli`) для проверки одной гипотезы
- Гипотеза: "The person agrees with the request."
- Результат: contradiction/neutral/entailment

**Код:**
```python
# --- MNLI MODEL ---
mnli_tokenizer = AutoTokenizer.from_pretrained("roberta-large-mnli")
mnli_model = AutoModelForSequenceClassification.from_pretrained("roberta-large-mnli").to(device)
mnli_model.eval()

mnli_labels = ["contradiction", "neutral", "entailment"]

def mnli_reaction(text):
    if not isinstance(text, str) or text.strip() == "":
        return None

    hypothesis = "The person agrees with the request."

    inputs = mnli_tokenizer(
        text,
        hypothesis,
        return_tensors="pt",
        truncation=True,
        max_length=128
    ).to(device)

    with torch.no_grad():
        outputs = mnli_model(**inputs)

    probs = torch.softmax(outputs.logits, dim=1)
    return mnli_labels[int(torch.argmax(probs))]
```

**Результат:** `full_dialog_with_reactions.csv` (колонка `mnli_reaction`)

**Проблемы:**

### Этап 7.2: Решение проблемы дисбаланса классов

#### Проблема:
После обучения модели выяснилось, что модель плохо распознает редкий класс "Отказ (0)":
- **Класс 0 (Отказ)**: precision=0.00, recall=0.00, f1=0.00
- **Класс 1 (Нейтрально)**: precision=0.75, recall=0.30, f1=0.43
- **Класс 2 (Заинтересован)**: precision=0.59, recall=0.95, f1=0.73

Модель практически не предсказывала класс 0, предпочитая более частые классы.

#### Решение: Class Weights + Macro F1

**Изменения в коде:**

1. **Добавлены веса классов (Class Weights):**
   ```python
   from sklearn.utils.class_weight import compute_class_weight
   
   class_weights = compute_class_weight(
       'balanced',
       classes=np.unique(train_df["label"]),
       y=train_df["label"]
   )
   ```
   - Автоматически вычисляет веса для балансировки классов
   - Редкие классы получают больший вес в loss функции

2. **Кастомный Trainer с весами:**
   ```python
   class WeightedTrainer(Trainer):
       def compute_loss(self, model, inputs, return_outputs=False):
           loss_fct = CrossEntropyLoss(weight=class_weights_tensor)
           loss = loss_fct(logits, labels)
           return loss
   ```
   - Использует `CrossEntropyLoss` с весами классов
   - Модель больше "наказывается" за ошибки на редких классах

3. **Изменена метрика для выбора лучшей модели:**
   ```python
   metric_for_best_model="f1_macro"  # Вместо "f1" (weighted)
   ```
   - **Macro F1** учитывает все классы одинаково
   - **Weighted F1** учитывает частоту классов (не подходит для дисбаланса)

4. **Улучшенная функция метрик:**
   ```python
   def compute_metrics(eval_pred):
       # Вычисляет и macro, и weighted метрики
       f1_macro = ...  # Для выбора лучшей модели
       f1_weighted = ...  # Для сравнения
   ```

**Ожидаемый эффект:**
- ✅ Класс 0 (Отказ): recall должен вырасти с 0.00 до 0.3-0.5
- ✅ Класс 1 (Нейтрально): recall может вырасти с 0.30 до 0.4-0.5
- ✅ Класс 2 (Заинтересован): precision может немного снизиться, но recall останется высоким
- ✅ Общий macro F1 должен значительно вырасти

**Почему этот подход:**
- ✅ Быстро реализуется (2-3 строки кода)
- ✅ Не требует дополнительных данных
- ✅ Стандартное решение для дисбаланса классов
- ✅ Macro F1 учитывает все классы одинаково

**Важно:** После исправления контекста (Этап 7.1) модель нужно **переобучить** с правильными данными, чтобы она видела полный контекст диалогов.

### Этап 9: Классификация через LLM (Ollama) (декабрь 2024)

#### Скрипт: `bsp2/test_batch_interest.py`

**Проблемы предыдущих подходов:**
- Fine-tuned модель требует обучения на размеченных данных
- Недостаточно размеченных данных (особенно отказов)
- Калибратор на MNLI-признаках менее гибкий

**Что изменили:**

1. **Использование LLM (Ollama) вместо fine-tuned модели:**
   - Используется модель `qwen3:30b` через Ollama API
   - Не требует обучения на размеченных данных
   - Может использовать reasoning для лучшего понимания контекста
   - Более гибкий подход к классификации

2. **Упрощенная структура классификации:**
   - Только **3 категории** (без подклассов):
     - **0: Not Interested** - отказ или отсутствие интереса
     - **1: Neutral** - нейтральный ответ
     - **2: Interested** - заинтересованность или согласие
   - Упрощенный формат ответа: только число (0, 1, или 2)

3. **Batch-обработка диалогов:**
   - Все сообщения target (B4=1) в диалоге анализируются одним запросом
   - Более эффективно, чем обработка каждого сообщения отдельно
   - Полный контекст диалога передается в промпт

4. **Пропуск уже обработанных сообщений:**
   - Проверяется, обработано ли сообщение (есть значение в `interest_ollama`)
   - Если все сообщения в диалоге обработаны, диалог пропускается
   - Позволяет продолжать обработку с места остановки

**Структура категорий:**

```python
INTEREST_CATEGORIES = {
    "refusal": {
        "name": "Not Interested",
        "label": 0,
        "definition": "The person refuses to donate money or is not interested in donating."
    },
    "neutral": {
        "name": "Neutral",
        "label": 1,
        "definition": "The person neither agrees nor refuses, showing neutral response."
    },
    "interested": {
        "name": "Interested",
        "label": 2,
        "definition": "The person expresses interest in donating or agrees to donate."
    }
}
```

**Метод:**

```python
# Промпт просит вернуть только число:
# 0 = Not Interested
# 1 = Neutral
# 2 = Interested

# Формат ответа от LLM:
{
  "Message #1": 0,
  "Message #2": 1,
  "Message #3": 2
}
```

**Промпт:**
- Показывает 3 категории с их определениями
- Просит вернуть только число (0, 1, или 2)
- Использует полный контекст диалога для анализа
- Анализирует все сообщения target в диалоге одновременно

**Результат:** `test_batch_interest_results.csv`

**Структура:**
- Все колонки из `full_dialog.csv`
- `interest_ollama` - название категории ("Not Interested", "Neutral", или "Interested")
- `interest_label_ollama` - числовой label (0, 1, или 2)

**Преимущества:**
- ✅ Не требует обучения на размеченных данных
- ✅ Использует reasoning LLM для лучшего понимания
- ✅ Batch-обработка более эффективна
- ✅ Возможность продолжения с места остановки
- ✅ Упрощенная структура (только 3 категории)

**Ограничения:**
- ⏱️ Зависит от доступности Ollama сервера
- ⏱️ Время обработки зависит от размера модели и количества сообщений
